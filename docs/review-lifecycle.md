# 生命周期与扩展 Review

**仅在这些改动出现时读**：拥有/借用关系、异步任务、共享状态、关闭、取消、hook 或观测对象变化。先读 [Review 职责](review.md)；这里是增量检查，不是所有评审的必读清单。

## 沿对象与责任追踪

- 找真实创建者、owner、借用者及最后释放点；检查构造失败、部分安装、取消、重复关闭和在途任务。析构通知不能访问已销毁的派生对象；观测索引不得意外延长业务寿命。
- 列出共享状态的读写者及锁/线程或协程边界。判断同一不变量是否被同一同步机制保护；逐字段原子、分次取锁不能自动推出一致快照。
- 从调用者看关闭是否实现约定服务语义；再向内核对任务、回调、连接和借用资源最终由谁处理。不能用“内部回收中”掩盖责任悬空，也不能要求上层操纵内部状态机。

## 沿 hook 的真实调用点追踪

对照 [设计职责](design.md) 的“Hook 的控制契约”，检查实际执行位置、可修改的状态、并发配置、在途注销、重入和失败路径，而不只看公开说明。严格路径是否调用任意用户函数？卡住或抛异常后谁还能保证前进和清理？只读参数、实例级配置和 timeout 均不能单独证明安全。

## 验证调用者能看见的事实

- 超时、满载拒绝、重试、关闭后迟到结果与通知失败，有没有误报成功、丢失后果或重复副作用？
- 状态与诊断入口是否足以处理常见问题；性能/采样/快照承诺是否有来源，开销与限制有没有交代？
- 检查 [并发与生命周期用例](testcase-concurrency.md) 中与本改动相关的事件序列；只需能证伪当前风险的最小复现，不因读了专项就跑压力或全量测试。

**交回什么**：能成立的缺陷与证据，或明确无法证明的风险。不要把未复现等同不存在，也不把最后 diff 当作中间编辑历史的证明。
