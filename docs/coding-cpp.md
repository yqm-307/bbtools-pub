# C++ 编码规则

**何时读**：修改 C++ 实现、公开头或构建注册时；与 [编码职责](coding.md) 配合。以下是采用本规范的仓库约定，不推广为所有语言规则；目标仓明确约定优先。

## 语言、依赖与表达

- 以 C++17 为基线，不静默提升标准。标准库成熟能力先复用；不足时积极使用成熟、适合项目的 Boost 组件，不因“不是 std”而重复造轮子。再考虑仓内能力和确有必要的新依赖；新增依赖评估许可、安全、平台、维护、体积与退出路径。
- 类型、方法和函数用 `PascalCase`；成员用 `m_` 加 `camelCase`，非公开方法用 `_` 加 `PascalCase`；指针别名用 `Ptr`/`SPtr`/`UPtr` 后缀。枚举沿用模块风格，不借本任务重命名存量。
- 命名空间按模块组织，最多三层。模板服务于类型安全和复用，避免技巧性、难诊断的元编程。
- 优先 RAII、值语义和适当的智能指针；`SPtr`/`UPtr` 分别对应 `shared_ptr`/`unique_ptr`，裸指针用于明确的非拥有或受控关系。确需跨异步边界共享寿命才共享持有，不为微观性能破坏所有权。
- 错误用类型安全表达，状态用枚举，保留模块已公开的返回码契约；仅在确实保证不抛时声明 `noexcept`。工厂可用 `Create` 和 `PrivateTag`/受限构造约束创建路径。
- `volatile` 不提供线程间同步；跨线程状态按语义用 `atomic` 或锁，多字段一致快照不能仅靠逐字段 `atomic` 保证。时间和时长优先用 `std::chrono` 表达。

## 头文件与构建

- 公开类型有可定位的 `.hpp`；内聚小类型可共处，有非内联实现时配 `.cc`，不因类数机械加文件或层级。接口放 `interface/`，纯虚接口用 `I` 前缀；头文件用 `#pragma once`，目录与命名空间相符。
- include 按对应头、标准库、项目公共头、子模块头组织；公开头不泄漏内部类型或第三方物理栈、异常与线程模型，无法隔离时说明兼容影响并审查。
- 纯算法、类型工具和无状态小组件优先 header-only；稳定 ABI、重状态、I/O 或编译成本需要时保留编译单元。新模块与测试接入实际 CMake 目标，不引入新警告。
- `.clang-format` 是格式细则真源，`.editorconfig` 负责 UTF-8/LF 等文本约定。改动行按项目格式检查，存量全仓格式化另行决定；CI 的 `clang-format-diff` 不应借功能改动清洗全仓。
- 固定已验收的跨仓版本，失败的依赖或构建门禁不能换到底层命令绕过。CI workflow 只编排，执行逻辑放 `scripts/ci/`；CI 修改和系统安装需事先确认。

## 测试接入

- 沿用项目已选框架；每个测试源构建为独立目标，路径 `tests/<module>/Test_<行为>.cc`，CTest 名 `<module>.<行为>`。
- 按实际性质打 label：`smoke`、`unit`、`integration`（不依赖线上服务）、`live`（依赖外部服务）、`perf`。检查构建开关、CTest 注册集和 CI 执行路径，空过滤不是通过。
- 用例怎么选由 [用例设计](testcase.md) 负责；本节不重复行为测试方法。
