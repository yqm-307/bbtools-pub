# 文档与注释规则

**何时读**：编写或评审注释、README、指南、设计说明时。配合 [编码职责](coding.md) 或 [Review 职责](review.md)，不要求同时读取两者。

## 注释写当前契约和必要原因

- 中文为主，术语和标识符保留原样；assert、异常与控制台诊断用英文，业务 payload 不翻译。
- C++ 公开类、函数及文件职责用 `/** @brief ... */` 或 `///`，字段说明用 `///<`。按需说明参数、结果、执行域、寿命与错误；普通实现 WHY 注释不用机械加空标签。
- 不复述显然操作，不堆历史叙述；并发时序、所有权和资源约束不能为简短而删除。线程安全、快照一致性等承诺必须匹配实现。复杂关系确有收益才加小图，不搭文档网站或新 CI。

```cpp
// 差：调用 Close 关闭对象。
// 好：先停止接收新请求，避免关闭期间继续交出对象借用。
```

好例只演示写法，使用前核实实际行为。注释描述现在为何这样做；权衡放稳定设计文档，过程关联留 commit/PR，不在长期正文堆 Issue/PR 号、阶段代号、行号或临时版本。协议/RFC 与稳定 ADR 引用可保留。

## 文档各守一件事

| 位置 | 负责的内容 |
|---|---|
| `README.md` | 定位、最短使用路径和阅读地图；不超过 200 行，不复制正文或 API 全表 |
| `docs/architecture/` | 稳定架构与契约；区分目标和已实现事实 |
| `docs/decisions/NNNN-<slug>.md` | 决策及代价；编号递增且唯一，已合入正文不改，后续追加被哪条替代 |
| `docs/guides/` | 一个主题的实际操作方式 |
| 仓外或 PR/Issue/CI artifact | 运行日志、审查报告、阶段计划和会话记录，不混入长期规范 |

同一事实只有一处完整正文，别处链接；标题按主题命名，除 ADR 编号外不以日期/阶段编号组织。文档随相应代码一起更新，被替代正文删除、历史交给 Git；需要保留的旧入口仅导航，不复制一份过期规范。

## 示例与交付检查

- 示例放 `examples/<name>/`，附目的、运行方式和期望输出；断言及验收放 `tests/`。CI 编译示例，依赖外部服务的例子不在普通 CI 运行。
- 核对实际文件、命令、API 和链接，不能写不存在的入口或未提供的许可证。区分已实现、拟议、实测和未验证；运行 `git diff --check` 不等于内容正确。
- 公开前检查正文、示例、文件名和提交元数据，不含凭据、私有地址/绝对路径、原始日志或会话。人工脱敏与自动扫描分别说明，未运行就不声称通过；文档变更独立审查后再发布。
