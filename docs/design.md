# 设计职责

**何时读**：新增或调整 API、模块边界、生命周期、失败处理或扩展机制时。前置：[共用原则](principles.md)。职责是确定契约和取舍，不把方案描述当作实现或验证通过。

## 先确定责任，再确定接口

- 沿真实调用链写清拥有、借用和结束责任，包括异步工作完成前谁保证对象存活；成功、失败、取消、关闭都要能收口。
- 以用户要完成的动作设计默认路径。说明必要输入、结果和失败后的可选动作，不把内部对象图或回收步骤变成调用者协议。
- 边界以职责内聚为准；合并没有独立语义的转发与重复状态，保留确有不同责任的层。队列可薄封装，不预建万能 Manager/Factory/协议平台。
- 核心接口不依赖具体业务或扩展；传输适配层负责 I/O 与错误、取消和资源映射。依赖反转不改变源码依赖方向，消费者只依赖需要的模块。

## 把兜底写成用户能处理的行为

- **时间到了怎么办**：deadline 是“最晚等到什么时候”，timeout 是等待时长；用来避免异常无限等待，不让正常协作依赖超时碰运气。说明超时是否中止工作、是否可能已经执行；确实无法确认结果时显式表达未知，不把所有超时都混为同一种结果。
- **忙不过来怎么办**：说明容量边界以及等待、拒绝、限流、降级或丢弃策略。背压也可用于日常流控；谁承担重试、延迟、丢失、顺序变化等后果必须清楚，不能无界排队。
- **内部恢复后告诉用户什么**：按原则 P3 区分内部细节和外部影响；无法处理的失败必须给调用者可见信号。选择能承载这些后果的返回值、通知或状态入口；不能只把用户需要采取行动的错误藏在内部日志，通知本身失败也要有明确处理。
- **Close 关闭什么**：定义停止提供的服务、后续调用、在途任务和回调的可见行为，以及是否等待。自有资源的回收封在内部；不静默关闭借用的共享资源。仍占用资源或未完成工作若影响调用者决策，要暴露事实，而非要求用户管理内部回收链。Close 不等于销毁对象。

## Hook 的控制契约

只在需要扩展或观测的地方提供 hook，优先受限事件或只读快照。写清：

- 在哪个阶段触发、哪个线程或协程执行、是否持锁、同步还是异步。
- 能读写什么、能否挂起或重入、配置能否并发修改。
- 回调及其引用对象由谁持有，如何注销，注销后是否还有在途调用。
- 异常、阻塞、耗时过长如何影响主流程；会接触什么敏感数据。

关键不变量保护区、持锁路径、析构与准入安全边界，不执行无约束外部逻辑。任意回调不能靠“约定很快”或增加 timeout 就宣称可强制中止；不能把测试全局开关换个名字当正式扩展 API。

## 观测与取舍

- 按原则 P5 明确可用的状态、错误、统计和诊断入口，及细粒度能力的启用方式、开销、精度与限制。
- 观测不应意外保活业务对象、打破并发约束或泄露敏感数据；快照的一致性承诺必须与采样方式匹配。
- 对会影响选择的决定，说明收益、代价、能力上限和放弃的方案；用调用步骤、概念和排障路径比较，不以类数或行数代替复杂度判断。

**做到什么程度算够**：调用者知道如何使用及处理后果，实现者知道责任与不变量，关键风险有可验证的预期。沿用已有设计文档，不为每次改动强制新模板或会议；需要设计用例时转 [用例设计](testcase.md)。
