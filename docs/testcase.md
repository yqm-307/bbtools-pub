# 测试用例设计职责

**何时读**：为新行为、缺陷或覆盖缺口选择和设计用例时。前置：[共用原则](principles.md)。只运行既定测试时不重新做这套设计；发布放行归项目门禁，不由用例数量决定。

## 从契约选最小有效用例

1. 找到预期行为的来源，列出输入、结果、状态与副作用，先覆盖生命期和责任风险。现有实现不是预期真源；未知要求标明待确认，不编造断言。
2. 在能观察到风险的最低层级验证：纯逻辑用单元，公开边界用契约，跨模块或外部依赖用集成；只有低层级看不到问题时才上移。
3. 优先有效/无效输入、关键边界和失败恢复；涉及规则组合或状态变化时再增加对应序列。每例写清“前置 → 动作 → 可观察结果 → 断言”，并指出它能抓住哪一种错误。
4. 代入一个具体错误实现检查区分力；如果正确与错误实现都能通过，就调整输入或断言，不以覆盖率、通过数量或 mock 调用次数冒充保护能力。
5. 复用已有夹具，控制时间、随机源与外部响应。mock 用于隔离边界；接口接线的证明不等于真实后端行为，必要的真实集成证据不能用 fake 替代。

例如契约为 `stock >= requested`：`stock=4, requested=4` 能抓住误写成 `>`；只测 `requested=5` 抓不住这个边界错误。

## 按需展开

- 涉及并发、回调、关闭、取消、容量或超时：读 [并发与生命周期用例](testcase-concurrency.md)。
- 需要确定而非验证业务契约：转 [设计职责](design.md)，不能在测试里私自补规格。
- C++ 测试的文件命名、目标与 CTest 注册：只读 [C++ 规则](coding-cpp.md) 的“测试接入”。

## 证据和停止条件

交付关键用例及“契约依据、风险、可区分的错误、实际执行或未验证原因”。已执行时记录目标版本、命令、结果和必要副作用断言；失败先区分产品、测试和环境，不放宽断言或跳过失败装成全绿。

关键风险已有有效用例，或明确留下未知/未覆盖项，且新增案例不再改变结论时就停。纯文档用链接/内容检查，不硬造业务测试；未经授权不在共享或生产环境注入故障，不为本任务搭通用测试框架。
