# 并发与生命周期用例

**仅在这些风险存在时读**：并发读写、异步回调、取消/关闭、超时、容量上限或资源归还。先读 [用例设计职责](testcase.md)，只选与改动相关的序列，不把下面每条都当必跑任务。

## 建立可证明的交错

- 用同步原语或受控事件证明“已进入目标阶段”，再触发关闭、取消或故障；固定 sleep、反复重试碰运气不是阶段证据。
- 在责任交接前后选择边界：创建失败、发布前取消、执行中关闭、回调在途注销、重复结束、最后一个业务引用释放。观察结果与责任归还，不只检查最终返回成功。
- 并发快照断言整体不变量；对象寿命测试检查实际析构/弱引用失效，而不是用 Close 次数代替资源已回收。

## 观察结果之外的副作用

- 时间到期后检查工作是否仍可能继续、迟到结果如何处理、重试会否重复执行；不能假定 timeout 就证明远端未执行。
- 容量达到边界时检查接纳/拒绝/等待策略，以及取消、失败后额度是否归还；不为验证极端情况盲目满载本机。
- hook 测试覆盖与风险有关的异常、重入、阻塞影响和注销时序。复用正式受控路径，不另藏全局测试门；安全契约见 [设计职责](design.md)，测试身份不豁免它。
- fake 便于控制交错，但真实网络/外部系统的错误传播和资源行为仍需对应集成证据；不要用 fake 通过代替真实链路通过。

**执行边界**：有限并发、硬超时、可中止，临时资源能清理。失败保留目标版本与事件序列，区分实现缺陷、夹具错误和环境不足；不削弱断言、跳过失败或加盲目等待来凑全绿。
