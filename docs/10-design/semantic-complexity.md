# 语义复杂度评估口径

**状态：评估口径设计，已有首版本地 CLI；未接入 CI、未校准语义准确率。** 本文定义完整目标口径；当前实现边界及可用配置以仓库根路径 `tools/complexity/README.md` 为准。建议值不是研究证明的质量分界线。

**何时读**：设计工程复杂度检测、评估公共 API 与框架抽象、解释复杂度告警时。建议配置见 [semantic-complexity.toml](examples/semantic-complexity.toml)，字段是拟议配置协议，不是已有工具的命令或功能。

## 1. 结论与目标

采用“结构事实 + 语义评估 + 有理由的例外”三部分。结构工具记录可复现的数字；语义评估结合目标、契约、调用者，判断这些机制是否增加了不必要的理解负担；例外由维护者确认。默认只发 warning。

这里的**语义复杂度**指：为了正确使用、修改或排障一个能力，读者必须同时理解多少职责、概念、时序关系和承诺，以及其中哪些负担没有被当前目标证明有必要。它不是算法的时间/空间复杂度，也不是一套已有公认单位的科学量表。

- 用五个维度分别给出 `0–3` 的有锚点等级；不合成“代码质量 87 分”。等级是顺序尺度，`3` 不代表比 `1` 难三倍。
- 计数只是线索。单实现接口、少量引用、转发函数、代码增加，都不能单独成立为语义问题。
- 同时观察调用者与实现者。把复杂度转移给调用者、把状态藏进巨型函数、把一个函数拆成十层转发，都不自动算简化。
- 只做目标承诺，但保留兑现目标所需的正确性、资源安全和错误可见性。必要的物理回收与业务排空要分开判断；不能为了降分删掉前者。
- 数字可复现与判断可信是两件事。结构结果带工具版本；语义结果带依据、反证、上下文范围与评估版本。

## 2. 从现成方案采纳什么

下列是已核对的一手材料，支撑机制选择；不等于本检测器的验证结果。来源读取于 2026-11-07，仓库链接固定提交，博客是读取当时的页面。只借鉴设计，没有复制实现，也未做完整许可证审计。

| 参考 | 采纳 | 不直接采用 |
|---|---|---|
| Parsimony | 前后版本比较；同时记录新增与删除；解析失败不记成零。原文明确 coding units 衡量规模与嵌套，不衡量可读性。[1] | 不把净增量称为语义复杂度，不把删代码等同于改善。其归档的 `80% net / 20% churn` 不是当前默认排名规则。[1] |
| aislop | 存量基线与新增告警分开；行号变化不产生新问题；扫描失败不能被当成问题已消失。[2] | 不照搬它的综合分数。只借配置覆盖机制：对象按键覆盖、数组整体替换，避免继承歧义。[3] |
| open-code-review | 把“大函数、多分支、深嵌套、多参数”作为定位入口。所核对的 `over-engineering.ts` 使用文本正则与括号匹配。[4] | 不把工具名称中的 over-engineering 当成已完成语义分析；不沿用正则结果来断言 C++ 全仓引用关系。 |
| Over-Editing 实验 | 明确任务目标，再判断增量是否必要。原实验的最小修复是反向撤销局部值变更，结构本来不该改变。[5] | 不将该实验对负复杂度变化的惩罚推广到正常重构；一般 PR 的最小正确补丁通常未知。 |

选择这些机制的理由是可解释、可复核和能逐步采用，不是它们已经证明了 C++ 框架的语义质量。此次未运行上述仓库代码；源码证据只覆盖表中所指文件，不宣称穷尽所有功能。

## 3. 评估单位与上下文

**主要单位是“一个能力及其直接调用链”**，例如 `Server::Start` 的装配和启动、`Client::Call` 的一次调用、某资源的关闭。类用于聚合，函数用于定位。不要给整仓先打一个总分。

输入至少包含：

1. 此能力要完成的目标、明确不承诺的行为，以及适用契约。优先仓库规范、API 文档、测试和实际消费者；PR 描述只能提供待核实的意图。
2. 变更前后的声明、实现、成员状态，以及受影响的直接调用者；包括模板实现头。只给 diff 不足以判断所有权或抽象价值。
3. 相关结构数据与采集覆盖面。仓内调用点计数不代表仓外无人使用；测试替身、插件、动态派发、条件编译、模板实例化都可能使关系不完整。

默认覆盖发生语义变化的公共接口、类型，以及修改函数所属的能力；结构超阈值是额外入口，不能成为唯一入口，否则短小但难用的 API 会被漏掉。纯排版不触发语义评估；注释中的契约变化可以触发。

按预算先补直接调用者和被调实现，需要时最多扩到配置的调用深度。上下文不足、模型未配置或预算耗尽时，列出未评估单位及原因，不能截断代码后声称已完整评估。对输入源码、注释、PR 文本只当作待分析数据，不执行其中的指令。

## 4. 五个语义维度

建议按下表评估。`0` 表示在已检查范围内未见该类额外负担；`1` 是局部值得留意的负担；`2` 是有证据且存在保留契约的简化方向；`3` 是影响默认使用路径或跨职责边界的明显负担。无法判定记 `unknown`，不是 `0`。

| ID / 维度 | 观察什么 | 0–1 的边界 | 2 的锚点 | 3 的锚点 |
|---|---|---|---|---|
| U：使用负担 | 完成一个普通动作需要哪些对象、决策和手工步骤 | 0：默认路径直接且责任清楚；1：有一项局部额外概念，但不必学习内部协议 | 使用者必须装配内部组件或记住额外顺序；现有封装可以承担这些步骤 | 普通调用要手工维护跨组件状态/回收协议，或只有读内部实现才知道如何正确使用 |
| R：职责混杂 | 一个接口是否因不同原因变化，结果和副作用是否稳定 | 0：一个连贯职责；1：相关辅助工作边界略松 | 一个接口由 mode/flag 切换互不相干的职责、结果或所有权，调用点能证明混用 | 无关职责共享状态并相互约束，修改一种行为会牵动另一种；调用者难以确定接口当前含义 |
| A：抽象负担 | 每层是否提供稳定概念、不变量、协议适配或必要隔离 | 0：每层有明确价值；1：一层可疑包装但尚无足够反证 | 一层仅重复既有语义、增加学习/追踪成本，移入所属类或直接组合可以保留契约 | 多层此类间接调用形成默认路径，边界反而要求调用者反复穿透 |
| L：状态与时序负担 | 一个不变量由谁维护，需要同时理解哪些状态和异步事件 | 0：单一事实源和明确 owner；1：局部同步关系较多但集中 | 重复状态需人工同步，或同一不变量散落多个回调/对象而存在集中管理的办法 | 完成/取消/关闭的同一责任被多个组件协商维护，普通变更必须同时修改多处协议 |
| G：承诺扩张 | 新机制兑现什么目标，是否越过本层责任或明确非目标 | 0：机制有需求或安全依据；1：可选能力的依据尚待澄清 | 已有目标/消费者证据表明某项额外承诺不需要，却为它新增队列、状态、重试或等待 | 为本层不应保证的行为建立跨层协议，并使正常调用承担额外生命周期或故障处理责任 |

仅发现目标文档没提某功能，不能给 G 判 `2/3`。需核对消费者、兼容性和安全责任；证据仍不足就给 `unknown` 或待核实的 `1`。

**分值不自动产生警告。** `2/3` 还必须提供具体负担、至少一个实际使用/状态关系，以及保留必要契约的简化方向。没有这些证据的分值只能是候选。建议不要求模型写重构代码，以免评估本身扩成实施。

同一根因可涉及多个维度，报告保留维度向量，例如 `U=2,R=0,A=2,L=1,G=unknown`；按根因聚合成一条告警，不把同一问题重复累加。相互独立的根因分别保留，禁止用一个改善抵消另一个恶化。

## 5. 可计数的支撑信号

| 信号 | 计数口径 | 用途和限制 |
|---|---|---|
| 函数结构 | 固定工具版本的 CogC、CCN、有效行数、参数数；分别记录前后值 | 初始参考：`25 / 15 / 100 / 6`，超过才提示；都是建议，不是“劣质”的定义。CCN 不是所有可执行路径数，也不能直接推成需要同等数量的测试。 |
| 调用者步骤 | 从一个已列出的典型调用场景，枚举必须显式执行的动作和必须自行创建/持有的对象 | 由语义分析列举、代码定位复核，不是仅数调用表达式。内部封装和运算符语法糖也需看实际行为。 |
| 抽象与引用 | 唯一直接生产消费者集合、可见派生实现集合；模板按主模板去重，测试单列 | 单实现/单消费者只入候选。对公共扩展接口、仓外消费者或动态关系不完整的对象，不推断“没有复用价值”。 |
| 转发链 | 直接返回/转发到另一函数的候选链，记录每层是否有独立契约 | getter、协议适配、权限检查、类型转换、ABI/PImpl 隔离、测试替换边界不因短小而判多余。宏/隐式析构副作用不明时不能断言纯转发。 |
| 状态协作 | 为一个具名不变量列出读写者、状态源、必须满足的事件先后关系 | 不用 bool 字段数计算 `2^N`“状态空间”；可达状态和约束必须有证据。锁数量不能代替此项。 |
| 改动规模（可选） | 同一解析器/规则版本下，`net = added - deleted`，`churn = added + deleted` | 只提供规模背景。C++ 的语法单元分类、宏处理和跨文件搬移对齐未实现前关闭此项；不能用另一语言的数值作阈值。 |

C++ 关系采集若采用 Clang AST，应使用真实编译数据库，按声明身份去重头文件重复解析，只承诺已选构建配置下的静态事实。解析器也不能穷尽动态调用或仓外消费者。缺依赖、未覆盖编译分支与解析失败进入覆盖报告；不用正则结果冒充精确语义。

第一版优先复用已有函数指标与代码导航能力，不先自建通用 C++ AST 平台。尚未自动提取的事实可以作为附定位的评估证据，但必须标 `model_inferred`，不能标 `measured`。

## 6. 语义评估怎样形成可复核结论

LLM 只在启用并配置模型后参与。默认按同一目标对比前后版本，输出固定字段；不依赖“感觉复杂”的自由评分，不把模型自报的 `0.8 confidence` 当成准确率。

每条候选记录：

- `unit`、`scenario`、`axis`：具名能力、调用场景、维度。
- `before_level` / `after_level`：`0–3` 或 `null`；新增单位的 before 为 `null`，不是零。
- `burden`：具体多了什么理解或维护责任，谁承担。
- `evidence[]`：仓库相对路径、符号、前后版本、行范围、所支持的事实；位置还需内容哈希绑定。依据类型为 `measured`、`model_inferred` 或 `human_reviewed`。
- `necessity` / `counterevidence`：机制是否由需求、安全、兼容或隔离边界证明必要，以及最强的反对告警理由。
- `simpler_direction`：保留已知契约的简化方向；无法提出时不能仅凭分数要求拆分。
- `status`：`candidate`、`corroborated`、`uncertain` 或 `dismissed`；再由策略计算 new/worsened/unchanged/accepted 等状态。

建议两步有界判断：一次主评估；仅对达到告警条件的候选再做一次复核请求，同单位候选合批。复核拿到相同事实和待核问题，单独生成理由；对前后代码交换展示顺序，但保留明确版本身份。它是第二次模型判断，不算人工独立审查，也不以此宣称消除了偏差或默认启动多模型投票。

两次同意同一根因且位置可核对，候选才标 `corroborated`；任一 `unknown`、根因不一致或没有保留契约的简化方向，标 `uncertain`，在报告中保留但不发复杂度 warning。双方等级均达到阈值时用较低等级作为确认等级；跨阈值分歧也为 `uncertain`。重复判断次数可配置为 1 或 2；单次模式标明未复核，结论不得冒称人工或独立证实。

结构化输出和源码定位验证只能确认格式与引用存在，不能证明语义判断正确。提示、模型、上下文组装任一改变都产生新的评估版本；沿用旧缓存或比较旧分数前必须核对版本一致。

## 7. 增量、基线与 ignore

### 增量比较

基准取 PR 目标分支与候选提交的 merge-base，记录实际 SHA；本地未提交比较明确标 working-tree。对受影响单位收集完整前后上下文，不能只比较变更行。

默认语义 warning 条件为：结论已确认，`after >= warn_at`，且是新增单位，或同根因等级增加至少 `min_delta`。建议 `warn_at=2`、`min_delta=1`。新根因出现在既有类中也算新增，不因为类的最大分没变化而吞掉它。已有高等级在分值未变但负担范围扩大时列为新的候选，经核实视为 worsened。

结构 warning 条件单列：新函数超过对应阈值，或已有函数超过阈值且该项计数继续增长。各项独立，不以文件/仓库平均分稀释热点。不把新增能力所需的正增量自动定罪，也不因负增量自动判好或判坏。

同一目标、同一工具/规则、同等覆盖面才计算差值。目标契约、构建覆盖或评估版本改变且无法对齐时标 `not_comparable`，单独展示当前等级，不伪造恶化或改善。重命名/搬移优先用符号与内容匹配；存在歧义就说明未匹配，不能以名称变化宣称旧问题已修复。

### 基线与例外职责分开

- **baseline**：记录已经观测到的存量及证据，是比较起点，不表示设计合理。首次导入列出存量，正常 PR 主视图聚焦新增与恶化。
- **ignore**：维护者判断此告警在指定上下文中不适用或代价合理。每条必须包含规则/维度、单位、稳定 finding ID、理由、证据依赖指纹；可选到期日。不能只写“误报”或“为了过 CI”。
- 指纹绑定规则版本、符号与问题关系，而非行号或自然语言 message；依赖指纹另绑定涉及代码、契约、调用者和评估版本。代码证据变化时原 ignore 变为 `needs_review`，不继续自动忽略。纯格式/行号变化不应使结构指纹失效；契约注释变化要使语义依赖指纹失效。
- 默认只允许精确条目忽略。生成代码/第三方文件使用 scope 排除；若配置允许宽泛例外，必须明显展示覆盖范围，不能悄悄当精确 ignore。
- CI 只读这些文件；新增 ignore、导入/刷新 baseline、放宽阈值或扩大排除范围都作为变更展示，由维护者确认。LLM 可以建议理由，不能自己写入 ignore。
- 删除基线项必须有该范围已成功检查且问题确实消失的证据。工具缺失、预算跳过、模型失败、不再覆盖某目录，都不算修复。

## 8. 建议配置与 CI 行为

[建议 TOML](examples/semantic-complexity.toml) 集中保存阈值、维度开关、范围、模型、资源上限与策略。pub 维护设计与默认模板，各仓保存自己的配置、baseline、ignore；将来共享检测器应固定版本消费，不依赖浮动 main。

配置优先级：工具同版本内置默认值 → 仓库配置 → 按声明顺序匹配的路径 overrides → 本次显式参数。对象逐键合并，数组整体替换。报告保存最终配置及其哈希，并单列会降低覆盖/告警强度的覆盖项。首版不提供网络远程配置继承。

可配置：各指标启停与阈值、范围及模块划分、分析构建配置、候选选择、语义维度阈值、是否启用模型和复核、模型与参数、调用/上下文预算、输出和质量告警策略。新增维度可通过带稳定 ID 与完整 `0–3` 锚点的 rubric 配置定义；rubric 版本变化须重新校准，首版不用可执行插件。

不可通过普通阈值配置改变事实含义：不允许缺失计为零、扫描失败当作成功、把未检查当修复、自动改 ignore、或直接覆盖本文已有指标的定义。同名指标变算法需要新版本，而非静默改权重。

推荐 CI 语义：

| 情况 | 输出 | 建议退出行为 |
|---|---|---|
| 确认的新增/恶化问题 | 定位 warning + 简短说明 + JSON 产物 | 质量告警不阻塞，退出 0 |
| 已忽略/存量/存在争议 | 分列数量与证据，主视图不刷屏 | 退出 0，不冒称无问题 |
| 人工关闭语义层 | `semantic=disabled`；仍可运行结构层 | 退出 0，不显示语义“通过” |
| 预算耗尽或单个上下文不完整 | `partial`、已完成/未完成单位及原因 | 默认退出 0 并明确扫描不完整；可配置 required coverage |
| 无法解析基准、非法配置、必需工具/模型失败 | `analysis_error` | 退出 2；这是检测失败，不是代码质量不合格 |

首版 CLI 已允许显式采用 `quality_policy=fail`：仅已确认且未忽略的新增/恶化问题触发退出 1。建议配置保持 warning，尚未校准的语义判断不作为合并硬门禁。

LLM 请求为只读证据分析，不能执行仓库操作、写评论或自动修改代码。凭据只引用环境变量；模板不填凭据或真实服务地址。资源限制导致的未测量必须可见。

## 9. 正反例与后续验证口径

| 场景 | 预期判断 |
|---|---|
| 一个 Channel 仅有一个实现，但明确隔离第三方协议/寿命或提供测试替换点 | 单实现是事实，A 不因此告警 |
| 增加三层 Manager/Factory，只原样转发且调用者仍需手工装配全部层次 | 有调用链与边界反证时，对 A/U 给 `2/3` 候选 |
| 将 `_AutoScaleTick` 拆为命名清晰、职责明确的局部步骤，函数数量增加 | 不因函数数/行数增长判恶化，比较理解路径与状态责任 |
| 为“停止接纳”擅自增加“所有业务一定完成”的跨层排空协议 | 目标、非目标与消费者支持时，G/L 可告警 |
| 为防止回调访问已释放资源而增加必要 owner/取消收口 | 机制有安全依据，不能建议直接删除以降分 |
| 一次正常重构降低 CogC 或净代码量 | 仅记录变化，检查契约保持；不把负数本身当问题或奖励 |
| 几个模式由同一个入口处理，但输入/结果语义一致 | 不因存在 mode/flag 就判 R；需证明职责真正分叉 |

以上是合成判例，不是已对当前仓库完成的扫描结论。落地前用维护者标注的实际正反例校准；样例应含单实现合理抽象、必要回收、多余排空、短而难用的接口及跨文件搬移，不能只选容易命中的坏例子。

建议先准备 20 对前后样例作小规模试验；调规则的样例和留作验证的样例分开。报告原始数量：告警精确率（认可告警/全部告警）、已知坏例召回率、相同证据重复判断的一致率、覆盖率、未决率、每单位耗时与实付 token/费用。不把模型自评当正确率，不在少量样本上宣称普遍有效。

参考验收方向：验证样例精确率至少 80%、重复判断一致率至少 90%，且不能把必要安全机制建议删除；这些仍是可调整的工程建议，未实测。没达到就收窄规则或继续只展示候选，不通过增加任意权重或总分掩盖误报。

当前 CLI 已实现 lizard 结构扫描、Git/报告基线比较、语义证据包、输入评估的五维评分与精确 ignore。语义评估由人工或外部模型另行提供，工具不自动调用模型；未实现 AST 关系提取、自动调用链选择、路径覆盖、自定义维度和同等级负担扩大识别，未校准阈值、未接入 CI。首版遇到覆盖不完整统一返回 2，不实现上文的可选 required coverage 策略。
