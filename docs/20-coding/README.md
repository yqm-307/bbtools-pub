# 编码职责

**何时读**：实现或修改代码时。先在根路由进入共用原则，再进入本文件；本文件只负责把已明确的契约做实，不用实现偶然行为替用户补规格。C++、公共头、构建注册、注释或文档触发专项时，再进入本目录对应文件。

## 本次编码负责什么

1. 读受影响代码、真实调用者和失败路径，先确认所有权、异步寿命、资源归还和公共语义。
2. 复用已有实现、标准库和项目已选能力，做最小充分改动；发现重复先找共同原因，不逐调用点复制修补。
3. 保持接口、错误、取消、关闭、容量和观测责任一致。不能为了少代码删除 deadline、背压、错误可见性、资源归还或未知结果。
4. 用能证明改动的最小检查验证；保留真实失败，区分未跑、跳过、失败和通过。
5. 同步受影响的稳定文档和示例，写明实际修改、证据、未覆盖范围和副作用。

## 一次改动的最短路径

### 先看调用关系

正例：修改队列入队函数前，找到生产者、容量检查、等待者、取消路径和释放点，再决定改入队处还是共享收口处。

反例：看到两个调用点都失败，就各加一个 if，未检查它们是否共享同一责任缺口。

### 再定最小实现

优先级通常是：现有辅助函数 → 标准库 → 已选成熟依赖 → 最小新代码。C++ 项目需要时进入 [C++ 编码](cpp.md)；公开注释、README、指南或设计说明进入 [文档与注释](documentation.md)。

正例：标准库已能表达明确的所有权，就使用 RAII 和现有类型，不另造一层包装；确有成熟 Boost 能力且项目允许时，说明为何复用它。

反例：为了避免一个小函数，新增万能基类、全局事件总线或一套配置系统；或者因为实现短就把非拥有关系改成共享持有。

### 最后核对影响

检查公共接口、错误文本、线程/协程域、构建目标、测试注册和文档路径。实现完成不等于独立 Review、CI 或发布通过。

## 函数读不出意图时按阶段拆分

**信号**：读者无法一眼说出这个函数在做什么；函数体把计数、阈值、取整、重试、持锁范围等细节全部展开；多个阶段共用局部变量，中间夹着 early-return。

**做法**：入口函数只保留阶段骨架，每个阶段交给一个用意图命名的函数；纯算术拆成无状态小函数。

- 阶段函数用意图命名（采样、累计、决策），不用 `Part1`/`DoStep2`；要求调用方已持锁的辅助函数带 `Locked` 后缀。
- 锁的持有范围留在入口函数，不让辅助函数各自加解锁，以免改变锁序。
- 拆分是纯结构改动：early-return 的先后、状态副作用发生的位置、锁序都不变；发现需要改行为，另做一次改动。
- 只有一条线性逻辑、拆开后要来回跳读的函数不拆；拆不出有名字的意图，就说明这个边界不对。
- 验证用原有聚焦测试，再做一次变异（让某个分支永不触发），确认测试会变红；若测试靠源码锚点或探针注入，要同步更新锚点，并优先选单行、不易被重排影响的锚点。

正例：入口函数 `_AutoScaleTick` 只有"门禁 → 采样 → 累计 → 决策 → 唤醒"五步，每步一个函数（`_ClaimAutoSampleLocked`、`_SampleScalingLoadLocked`、`_AccumulateScalingHitsLocked`、`_ApplyScalingDecisionLocked`），读入口就知道一拍做什么；几行就能读完的取整和封顶留在所属阶段里，不再单独拆成函数。

反例：同一个函数里先做模式检查和间隔检查，再读快照、遍历队列算占比，再逐个比较阈值、更新两个计数器，最后分扩缩两支各自算目标、调用提交、按返回码复位计数。每个细节都对，但读者必须读完全部才知道它在做"自动伸缩的一拍"。

## 修正 badcase 时保持当前真相

实现、公共接口、测试、文档或提示词一起发生语义变化时，先找到旧概念的所有使用点，再直接把它们改成当前概念。不要在旧注释、旧错误文本或旧提示后追加“因为某 issue 所以现在……”来掩盖没有完成的迁移。

正例：接口从“返回已完成”改成“返回已接纳、结果可能未知”，同步修改实现状态、调用者文档、测试断言和提示词中的处理方式；保留一个 `OutcomeUnknown` 回归用例。

反例：代码已经返回未知状态，文档仍写“成功/失败二选一”，再补一句“#213 后偶尔会出现第三种情况”。这会让当前读者继续按旧契约使用。

如果 badcase 只影响历史排查而不改变当前使用方式，保留在 commit、ADR、审查报告或私有证据；只有后来维护者必须据此做兼容、迁移或安全判断时，才在当前正文留最小背景。

## 按需展开

- C++ 实现、公共头、CMake 测试接入：读 [C++ 编码](cpp.md)。
- 注释、README、指南、设计说明或公开脱敏：读 [文档与注释](documentation.md)。
- 需要重新决定 API、所有权、关闭或错误语义：回到设计职责层重新澄清，不在实现中偷偷改规格。
- 新增行为或修复覆盖缺口：进入用例设计层；已确定测试命令时不重新发明测试选择流程。

## 边界和停止条件

不夹带无关重构、全仓格式化、新工具链、CI 改写或系统安装。关键责任已有实现和检查证据，新增改动不再改变结论，就停止；把仍未知的事实写出来，不用“应该没问题”收尾。
