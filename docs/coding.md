# 编码职责

**何时读**：实现或修改代码时。前置：[共用原则](principles.md)。职责是把已明确的契约做实；发现契约缺口先查清，不用实现偶然行为替用户决定。

## 本次负责的事

1. 理解受影响代码、真实调用者、所有权及失败路径；复用现有实现和标准能力，做最小充分改动。
2. 保持接口、验证、错误与资源责任一致。不能为少代码删保证，或在无授权时改变公共语义；重复逻辑先找共同原因，不逐调用点打补丁。
3. 选择能证明改动的最小检查，保留真实失败。改动收敛后集中验证；纯注释不机械重跑整套行为测试，但必须核实没有改坏契约或代码。
4. 同步受影响文档及示例，交代修改、证据、未覆盖项和副作用；实现完成不等于审查通过、CI 通过或已发布。

## 按需展开

| 本次涉及 | 再读 | 不必因此加载 |
|---|---|---|
| C++ 实现、公共头或 CMake 测试接入 | [C++ 规则](coding-cpp.md) | 不涉及的语言或工具规则 |
| 公共注释、README、指南或设计文档 | [文档与注释](coding-documentation.md) | 产品运行与并发测试专项 |
| 需要决定 API、所有权或关闭/错误语义 | [设计职责](design.md) | 已确定契约的重新设计 |
| 新增行为或修复需补回归用例 | [用例设计](testcase.md) | 已确定测试命令的重新选型 |

**边界**：不夹带无关重构、全仓格式化或新工具链；不靠可回滚扩大提交、发布、CI 或系统安装权限。完成上述范围即交付，不替独立评审者放行自己写的内容。
