# 并发与生命周期用例

**仅在这些风险存在时读**：并发读写、异步回调、取消/关闭、超时、容量上限、hook 注销、观测对象变化或资源归还。先读用例设计入口；这里只补交错和责任检查，不把每条都变成必跑任务。

## 1. 建立可证明的交错

用同步原语、受控事件或屏障证明“已经进入目标阶段”，再触发关闭、取消或故障。固定 sleep、盲目重试和“多跑几次”不是阶段证据。

典型序列：

```text
创建 → 发布 → 确认已进入目标阶段 → 触发取消/关闭/异常
     → 等待收口 → 检查结果、资源和最后引用
```

正例：测试回调注销时先由回调通知“我已进入”，主线程再请求注销，最后释放 owner，并断言在途调用的边界。

反例：启动线程后 sleep 10ms 就释放对象；一次没崩溃便声称没有 UAF。

## 2. 在责任交接边界断言

重点覆盖创建失败、发布前取消、执行中关闭、回调在途注销、重复结束、最后一个业务引用释放和通知失败。观察责任归还和副作用，不只检查最终返回成功。

正例：队列满载后取消等待者，检查等待节点和额度都归还；Close 后迟到结果进入明确的丢弃、未知或查询状态。

反例：只断言队列返回“拒绝”，不检查拒绝路径是否留下额度；只数 Close 调用次数，不检查实际资源或弱引用是否失效。

## 3. 共享快照和寿命

并发快照应断言整体不变量；如果多个字段必须一致，就用真实同步协议或版本校验。对象寿命测试检查实际析构、弱引用失效或资源释放，不把逻辑 Close 当作物理回收。

正例：生产者在写入开始/结束有受控事件，读者只在协议允许的阶段取快照，并验证不会出现“总数小于已完成数”的组合。

反例：分别读取多个 atomic 后拼成“同一时刻快照”；看到 Close 返回就断言派生对象已经析构。

## 4. 时间、容量和 hook

- 时间到期后检查工作是否仍可能继续、迟到结果如何处理、重试是否重复执行；不能把 timeout 当作远端未执行。
- 容量达到边界时检查接纳/拒绝/等待策略，以及取消、失败后额度是否归还；不为极端场景盲目满载本机。
- hook 测试覆盖与风险有关的异常、重入、阻塞影响和注销时序；复用正式受控路径，不另藏全局测试门。
- fake 适合控制交错，真实网络/外部系统错误传播和资源行为仍需相应集成证据。

正例：用受控 callback 阻塞点证明关闭期间的行为，再释放点让主流程继续；断言异常后状态和额度仍能收口。

反例：在严格路径中用任意用户函数制造阻塞，再以测试没有死锁一次作为长期安全证明。

## 5. 执行边界

有限并发、硬超时、可中止，临时资源能清理。失败保留目标版本和事件序列，区分实现缺陷、夹具错误和环境不足；不削弱断言、跳过失败或增加盲目等待来凑全绿。需要真实 TCP 或外部集成时，明确 fake 只能覆盖哪一段。

做到关键风险已由可重复交错证伪，资源和副作用有断言，剩余未知已记录；新增案例不再改变结论时停止。
